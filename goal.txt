# Enterprise AI Agent Framework — Master Development Prompt

## ROLE

You are a Principal AI Systems Architect, Staff TypeScript/Node.js Engineer, and Enterprise AI Agent Framework designer.

Your task is to design and implement a production-grade, extensible **Enterprise AI Agent Framework** that allows application developers to build reliable AI Agents without reinventing the underlying infrastructure every time.

The framework must provide standardized abstractions and runtime capabilities for:

1. LLM fundamentals
2. Tool calling
3. Structured outputs
4. Context management
5. RAG / Knowledge
6. Memory
7. Planning
8. Reflection / Verification
9. Orchestrator / Worker architecture
10. Multi-Agent systems
11. Guardrails and Security
12. Observability
13. Evaluation
14. Production architecture

The framework will primarily target **Node.js + TypeScript**.

Do not build a toy chatbot framework.

Build a serious foundation that could eventually be used by multiple teams to build many different enterprise agents.

---

# 1. CORE TECHNOLOGY DECISION

Use:

* Node.js
* TypeScript
* Modern ESM architecture
* Strict TypeScript configuration
* Zod or an equivalent schema-validation library
* PostgreSQL as the primary relational persistence layer
* Redis where appropriate for caching, queues, locks, and ephemeral state
* OpenTelemetry-compatible observability
* Pluggable LLM providers
* Pluggable vector/database providers
* Pluggable storage providers

The framework MUST NOT be tightly coupled to one LLM provider.

It must support an abstraction similar to:

```text
Agent
  ↓
LLM Provider Interface
  ↓
OpenAI / Anthropic / Gemini / OpenRouter / Local Model / Other
```

The same principle must apply to:

* Vector databases
* Embedding providers
* Storage
* Queue systems
* Observability
* Authentication
* Memory stores

Do not hard-code a single vendor into the core architecture.

# 4. FRAMEWORK DESIGN PRINCIPLE

The developer experience should be extremely simple.

A developer should eventually be able to create an agent approximately like:

```typescript
const agent = defineAgent({
  name: "research-agent",

  model: models.openai("..."),

  instructions: `
    You are a research agent.
    ...
  `,

  tools: [
    searchTool,
    databaseTool,
    calculatorTool
  ],

  memory: memory.user(),

  knowledge: knowledge.base("company-documents"),

  output: ResearchReportSchema
});
```

Then:

```typescript
const result = await agent.run({
  input: "Research..."
});
```

The framework should handle the complexity underneath.

# 5. CORE PRINCIPLES

The framework must follow these principles:

## 5.1 Provider independence

No core component should depend directly on a specific AI vendor.

Use interfaces/adapters.

Example:

```typescript
interface LLMProvider {
  generate(...): Promise<LLMResponse>;
  stream(...): AsyncIterable<LLMEvent>;
}
```

---

## 5.2 Strong typing

Use TypeScript aggressively.

Avoid:

```typescript
any
```

unless absolutely unavoidable.

Use schemas for runtime validation.

---

## 5.3 Explicit state

Agent execution state must be explicit.

Example:

```typescript
interface AgentState {
  runId: string;
  agentId: string;
  status: AgentStatus;
  input: unknown;
  context: ContextState;
  plan?: Plan;
  steps: ExecutionStep[];
  memory?: MemoryState;
  metadata: Record<string, unknown>;
}
```

---

## 5.4 Deterministic core

LLMs should not control:

* authorization
* security policies
* billing
* permissions
* irreversible actions
* audit logging
* system invariants

The framework must enforce these deterministically.

# 8. STRUCTURED OUTPUTS

Provide a standard mechanism for:

```typescript
output: MySchema
```

The framework should:

1. Ask the model for structured output
2. Parse it
3. Validate it
4. Retry/correct if appropriate
5. Return typed data
6. Record validation failures

Example:

```typescript
const ReportSchema = z.object({
  summary: z.string(),
  findings: z.array(z.string()),
  confidence: z.number().min(0).max(1)
});
```

# 9. CONTEXT MANAGEMENT

Build a dedicated Context Engine.

Do NOT simply send the entire conversation to the model.

The Context Engine should manage:

* System instructions
* Agent instructions
* User input
* Conversation history
* Relevant memories
* Relevant knowledge
* Tool results
* Current task state
* Previous execution state
* Summaries
* Token budgets
* Context priorities

Implement context selection/compression strategies.

Concept:

```text
Available Information
        ↓
Relevance
        ↓
Priority
        ↓
Token Budget
        ↓
Final Model Context
```

The framework must support context policies.

Example:

```typescript
context: {
  maxTokens: 16000,
  includeMemory: true,
  includeToolHistory: false,
  summarizeHistoryAfter: 20
}
```

# 11. MEMORY SYSTEM

Separate memory from knowledge.

Support:

### Short-term memory

Current execution.

### Conversation memory

Previous conversation.

### User memory

Long-lived user preferences/facts.

### Entity memory

Information about organizations, projects, customers, etc.

### Episodic memory

Important previous events.

### Semantic memory

Extracted reusable knowledge.

Memory operations:

```typescript
memory.get(...)
memory.search(...)
memory.store(...)
memory.update(...)
memory.delete(...)
```

Memory must have:

* TTL
* Scope
* Ownership
* Permissions
* Metadata
* Confidence
* Provenance
* Lifecycle management

Do not automatically save everything.

Memory should have policies determining what deserves persistence.

# 13. REFLECTION / VERIFICATION

Implement verification as a first-class capability.

Support:

```text

 ↓

```

Verification strategies should include:

* Schema validation
* Rule validation
* Tool-based verification
* Source verification
* Deterministic checks
* LLM-based critic
* Cross-agent verification

Make reflection configurable:

```typescript

  strategy: "verify",
  maxAttempts: 2
```

# 39. ANTI-PATTERNS TO AVOID

Do NOT create:

### Giant Agent

One agent with 100 tools and unlimited permissions.

### Giant Prompt

Putting the entire application architecture into one system prompt.

### Infinite Agent Loop

Agent repeatedly calling itself without hard limits.

### Blind Memory

Saving every conversation permanently.

### Blind RAG

Retrieving dozens of irrelevant documents.

### Fake Reflection

Having the same model say "I am correct" without evidence.

### Uncontrolled Multi-Agent

Agents spawning agents without limits.

### LLM Authorization

Letting the LLM decide whether it has permission.

### Hidden State

Agent state existing only inside prompts.

### Vendor Lock-in

Putting provider-specific APIs everywhere.
